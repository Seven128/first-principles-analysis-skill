# 成文检查

检查目标不是判断文章像不像某位作者，而是定位：文章是否在保持推演不变量的同时，降低了读者获得正确理解的成本。

## L1：语言与表面负担

### 1. 元叙述

检查可删除且不增加信息的开场和转场，例如：

- “本文将……”；
- “值得注意的是……”；
- “进一步来看……”；
- “下面我们分析……”。

删除后不影响事实、关系或结构时直接删除。

### 2. 术语一致

同一概念默认使用同一名称。第一次出现时说明普通语言含义，后文不为变化感不断更名。

### 3. 抽象名词

检查“进行、实现、能力、机制、体系、层面、建设、赋能”等组合。能还原成明确主体和动作时改写；正式术语更准确时保留。

### 4. 超载句

检查一个句子是否同时承担多个独立结论、多个新术语或多层嵌套。发现后拆句，并保留真实连接。

句长、逗号数量和新术语数量只作为预警，不能机械判错。

### 5. 指代与省略

检查“它、这、该机制、上述内容”等是否能在当前句或相邻句明确定位。需要回到远处确认时，直接写出对象名称。

## L2：结构与关系

### 1. 结论出现速度

核心问题、对象或条件化结论应尽快出现。背景只有在理解核心结论前确实需要时保留。

### 2. 段落单一功能

每段应能用一句话概括主要新结论。一个段落同时解释多个不同问题时，按逻辑单元重组。

### 3. 因果显式

完整推演已经证明的依赖应在文章中可见。不能把“问题—能力—新问题—后续机制”压成一组属性。

同时检查反方向错误：并行事实不能被写成未经证明的因果。

### 4. 局部理解负担

连续几句是否同时引入过多新概念、关系和字段？若是，按依赖拆开，先建立前一关系，再引入后续术语。

“不密”不等于全部使用短句。高负载句后可以用直接解释、具体动作或换段完成闭合。

### 5. 结构推进

连续阅读每段首句，是否能看出文章从起点走向结论？若只能看到模块名，说明段落骨架仍由目录驱动，需要回到因果主线重组。

## L3：内容保真与信息选择

### 1. 推演不变量

逐项核对：

- 核心结论；
- 关键事实；
- 重要因果边；
- 条件和不确定性；
- 评价标准；
- 用户点名的关键内容。

### 2. 信息选择

每项正文信息是否改变理解、判断或行动？若只是展示研究过程、完整字段、被排除分支或重复背景，删除、合并或移到补充部分。

### 3. 例子效用

每个例子应有明确功能。重复正文、功能相同或细节过多的例子删除或压缩。

### 4. 边界靠近结论

限制、版本范围和不确定性应放在对应判断附近。不要把全部边界堆到开头或结尾，让读者先形成过强结论。

### 5. 辅助材料

表格、代码、流程图和引用是否比连续文字更有效？若只是重新展示正文，删除。

## L4：整体阅读检查

### 1. 一遍可跟随

通读时是否频繁回头确认主体、术语和关系？出现回读点时，定位到具体句子或段落，局部修复。

### 2. 高信息量但局部不过载

读完后获得的信息是否多，同时没有连续的明显过载点？若信息丰富但阅读中多次停顿，问题通常在关系平铺、术语提前或段落混杂。

### 3. 直白但保持专业准确

文章是否依赖“高级词感”表达，或者为了口语化删掉了精确概念？目标是普通语言解释专业关系，不是把专业内容改成幼稚说法。

### 4. 修辞收益

故事、幽默、类比和比喻是否确实减少理解成本或增强必要记忆？删除后更清楚时删除。修辞不能承担证据作用。

### 5. 语气适配

语气是否符合用户、读者和文章任务？默认不强制个人化、聊天感、情绪和作者姿态。

## 修复顺序

发现问题后按以下顺序处理：

1. 先修复事实、因果和边界不一致；
2. 再修复段落骨架与依赖顺序；
3. 再修复句子超载、抽象名词和指代；
4. 再删除重复、无关细节和低效例子；
5. 最后调整节奏和可选语气。

优先局部重写，不因一个句子有问题而重新生成全文。每次局部修改后，重新核对推演不变量。

## 自动检查的边界

可以自动或半自动检查：

- 元叙述和高风险措辞；
- 术语是否频繁更名；
- 长并列、多个独立谓词和新术语；
- 重复段落和重复案例；
- 类比、比喻触发词；
- JSON、路径和回归结构。

仍需要人工或模型整体判断：

- 因果是否保真；
- 并列是否被误写成因果；
- 删除后是否损失正确理解；
- 例子和比喻是否真的有收益；
- 文章是否一遍可跟随；
- 用户偏好的语气是否达成。

自动指标是预警工具，不能替代理解测试和成文评审。
