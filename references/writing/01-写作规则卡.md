# 写作规则卡

本文件把“简洁、直白、直接、信息密度高而不密”转换成成文操作和示例，不重新分析事实和因果。局部结论与名称标题遵守 `references/core/05-输出与表达规则.md` 第 5 节；去套话与术语保真遵守第 6 节；段落、例子和证据展示的细则统一见 `references/writing/04-信息密度、段落与例子控制.md`。

## 0. 先完成分析交接与文章契约

成文前必须已有语义锁定的分析定稿，并建立文章类型、读者任务、范围、详细程度、视角和载体的契约。标题之后先写简短的读者可见问题，支撑问题、必须覆盖项和证据边界分别传递，不复制成长问句。目的结构适用时，继续保留最终目的、当前状态与要解决的问题、采用的方案。

现状部分先确定主要缺口，原因、表现、当前应对和后果放在对应问题下，独立限制另行保留。背景比较不能取代主问题。问题选错、层级不成立或重要限制遗漏时，返回分析修复；不能只给原句换词。

### 名称标题、结论句与解释段

方案标题可用准确名称或具体动作，如“工具调用”“持久化记忆”“保存任务进度”。紧邻正文直接说明作用和必要因果。完整陈述要求针对实际结论句，不要求把所有标题扩写成职责说明。

| 当前职责 | 示例 |
| --- | --- |
| 对象定位 | Agent 是基于大模型接口的通用任务执行应用。 |
| 执行缺口 | 大模型依赖外部程序执行操作。 |
| 多轮问题 | 开放性任务通常需要多轮判断与执行。 |
| 对应的当前应对 | 各轮结果仍由人传递。 |
| 方案标题 | 工具调用 |
| 紧邻正文 | 程序执行模型提出的请求，并把实际结果返回模型。 |
| 跨会话方案标题 | 持久化记忆 |
| 紧邻正文 | 保存任务目标、进度和结果，供下次会话继续使用。 |

这些是限定场景的表达示例，不是所有主题的固定答案。“各轮结果仍由人传递”属于这里的多轮衔接问题，不另设同级主要问题。跨会话保存与本轮输入选择同时出现时，使用“记忆与上下文管理”并分别说明，不能压成一个漏掉职责的短词。

定位句只说明类别、核心职责与必要范围，规划、反馈、状态和验证在对应问题出现后展开。名称已经足够时，不再用包含全部主体和责任边界的长标题替换。

### 直接陈述主答案

以下变换依据给定的验证和停止关系，不断言所有产品都有相同实现：

| 原表达 | 直接表达 |
| --- | --- |
| 停止原因需要与成功分开。 | 停止原因包括任务完成、执行受阻、人工取消和预算耗尽。 |
| 验证本身也有边界。 | 验证结果只支持实际检查过的要求。 |
| 参数格式正确不等于操作正确或操作被授权。 | 工具调用分别检查参数格式、操作权限和业务条件。 |
| 两种检查的强度不同。 | 提示词依赖模型遵循；程序检查可以拒绝缺少规定证据的完成请求。 |

最后一个例子以完成入口由程序控制为前提；没有该事实就不能这样改写。“测试尚未执行”“目前无法确认原因”等必要否定与不确定判断继续保留。优先说出实际关系，不机械禁用否定。

已经足够的内容可以保持原样，例如“阶段契约规定当前阶段的输入、产出和完成条件”。只需说明职责时就在这里结束，不强配解释、例子和小结。

## 1. 一句推进一个主要关系

### 解决的问题

一句同时承载多个事实、条件或结论，或者虽短却没有回答当前问题。

### 生成规则

先选准主要结论，再把答案说全。一个句子围绕一个主要新关系；多个独立结论优先拆开，保留真实连接。名称标题与紧邻正文共同完成当前要点。

### 适用与例外

紧密比较可以有两个分句，横向比较可以用表格。必要否定、条件和不确定性保留，不按固定字数判断。

### 常见失败

机械拆短后仍让读者归纳重点；删掉真实条件；用句号与粗体包装“有边界”；为完整句而扩写准确名称；定位句提前列后文目录。

### 改写示例

当前只解释进度保存时，标题可以写“保存渲染进度”，正文写：

> React 把渲染进度保存在 Fiber 中，以便暂停后继续计算。

再按需要解释进度如何从调用栈变成可保存的数据。分片、优先级和提交仍在对应问题下展开，不因局部变短而删除。

### 检查

结论句隐藏后文证明后是否仍给出具体判断？名称标题连同紧邻说明是否说清方案和作用？缺少依据时返回分析，不以长短代替语义检查。

## 2. 从平铺属性中恢复真实依赖

### 解决的问题

正文只列机制，读者要自行推断它们为什么出现。

### 生成规则

已证明先有 A 才能推出 B 时，按依赖解释；机制处理前一项带来的新问题时，紧接前项说明。已成立的局部结论可以先呈现，再给依据。

### 适用与例外

技术、制度、行业、行为和方案均可使用。没有证明依赖时保留并列或未知。

### 常见失败

为了顺滑制造因果，或把完整关系压成标题目录。

### 改写示例

“工具、反馈、权限、状态和记忆”只列了名称。解释段还需说明：

> 模型提出的操作由工具执行，实际结果返回模型供下一轮判断。真实操作可能产生副作用，因此需要权限约束。任务跨越多轮时，还需保存必要进度；跨会话继续则要求进度在会话结束后仍可恢复。

这段用于解释机制来源，不替换定位句，也不要求父节讲完之后再由子节重复。

### 检查

连续名词是否有未表达的依赖？有依据才展开，没有依据不制造因果。

## 3. 抽象名词还原为主体、动作和状态变化

### 解决的问题

职责描述遮住简单动作；重复补出已知主体和范围，增加阅读负担。

### 生成规则

删除重复主体、转折铺垫、无效限定、职责重复和展示性包装。先点明实际方案或动作，保留改变结论的条件。原材料没有的动作和效果不得补造。

### 适用与例外

准确术语、引语、精确标识符、真实比较和证据限制保留。责任归属容易混淆时应明确主体。

### 常见失败

把抽象名词换成更长描述；短名称足够却写“应用接管模型……之间的衔接”；每句重复主体；先虚构对立再回应；删除“尚未验证”使结果变强。

### 改写示例

“执行状态持久化能力建设”作为标题可改为“持久化记忆”，正文说明保存什么、供何时使用。同时涉及状态保存和输入选择的一节，分别说明两项职责，不能为短而漏内容。

已知检查结果供模型下一轮使用时，直接写“把检查结果返回模型，供下一轮判断使用”。当前操作者不清楚时才补主语。材料只有“提供全面支撑”却没有具体作用时，应先补证。

### 检查

删除某个词或分句后，主体、动作、范围和确定性是否改变？不改变且不帮助理解时删除；改变时保留或放到对应说明。准确原句可以不改。

## 4. 细节在第一次成为必要答案时出现

### 解决的问题

介绍结构时一次展开全部字段和模块，读者尚未理解问题就面对实现百科。

### 生成规则

字段、模块、协议和术语成为当前问题的必要答案时再展开。用户明确要求参考手册时，可以集中列出，但与原理主文区分。

### 常见失败

因为属于某结构，就在首次出现时全部介绍；前置答案目录；每个字段强配定义、代码和例子。

### 改写示例

解释暂停遍历时，先说明保存当前位置和后续路径的需要，再介绍 `child`、`sibling`、`return`。`lanes` 与 `alternate` 在优先级和中间结果隔离的问题出现时解释。

### 检查

每项细节在当前位置解决哪个已经成立的问题？无对应时后移、合并或删除，不把写作安排本身写进成稿。

## 5. 段落分担阅读任务，共同完成论点

### 解决的问题

为论点完整而挤成长段，或逐句换段拆散紧密关系。

### 生成规则

按问题、过程、依据和边界分组。同一论点可以由相邻段落共同完成，不要求每段重复结论。细则见 `references/writing/04-信息密度、段落与例子控制.md` 第 2 节。

### 适用与例外

简单关系留在紧凑段落，独立短点完整回答就停止。结论标题下直接解释，名称标题下说明作用，不强制逐段加粗。

### 常见失败

固定句数分段、自动加粗首句、简单结论强配背景和小结，或一段同时解释多个独立机制。

### 改写示例

进度保存、优先级和中间结果隔离各有独立问题，可以分节。每项必要论证再按阅读任务分段，不在父节先完整复述全部内容。

### 检查

相邻段落是否共同保留完整因果？主要答案是否可见？名称标题配紧邻说明可以通过，不因标题较短而扩写。

## 6. 例子必须替正文完成一项工作

### 解决的问题

例子只换名词重讲正文，或有价值却出现过晚。

### 生成规则

例子在使机制可观察、串联因果、区分概念、展示边界或检验理解时保留。在第一次帮助理解处出现，可前置、嵌入或后置。场景复用与证据区别见 `references/writing/04-信息密度、段落与例子控制.md`。

### 适用与例外

直接语言足够时不加。假设例子明确说明性质，只映射已成立关系，不新增机制或冒充证据。

### 常见失败

各节重复完整案例；细节比机制复杂；用案例填证据缺口；固定间隔插例子或强制全部后置。

### 改写示例

搜索输入场景可以在优先级部分用一次，也可在不同节只展示当前新增关系。已交代的输入不重复，不为贯穿全文补造故事。

### 检查

删除例子是否造成理解损失？是否及时？多个例子是否同功能？说明性质和真实演示的支持范围是否清楚？

## 7. 先具体化，最后才考虑比喻

### 解决的问题

读者同时承担理解目标、比喻及映射的额外任务。

### 生成规则

先用字面因果、具体动作和状态变化，再判断例子或局部比喻是否更有效。这个优先级不要求例子等全文原理结束才出现。

### 适用与例外

读者缺少理解基础，熟悉参照物更易说明局部关系时可以类比；用后返回字面机制。

### 常见失败

一个概念连续使用多个比喻，暗示对象没有的属性，或让比喻成为正文主角。

### 改写示例

不必把可恢复计算形容成时间机器。直接说明保存当前位置、暂停后继续，并保留适用的调度与恢复条件。

### 检查

读者确实需要、参照物更熟悉、映射局部清楚、无错误属性且比直接解释更有效时才保留。

## 8. 删字不能删掉因果桥

读者可见问题和适用结构节点负责文章任务与因果位置，不能当作重复铺垫删除。

### 解决的问题

只剩“事实 A，所以结论 C”，中间作用过程 B 被删除。

### 生成规则

压缩重复与旁支时，保留关键中间关系和必要限定。关系可由结论后的解释承担，不要求全部挤进结论句；名称标题与紧邻正文共同表达要点。有用回指和互补的文字、展示可以保留。

### 适用与例外

读者可稳定补全且不易误解的常识步骤可以概括，但不能改变成立条件。

### 常见失败

把完整链压成模块目录，用“因此”掩盖缺失过程，或删掉必要否定和不确定性。

### 改写示例

只列工具、权限、状态和记忆不足以说明来源。正文应分别交代请求执行、结果反馈、操作副作用与任务延续的问题；标题仍可用短名称。

### 检查

检查每个“所以、因此、从而”的中间过程。删除后读者无法说明为什么得到下一步时，补回因果桥；短标题不意味着正文只能给摘要。
