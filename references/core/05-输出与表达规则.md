# 输出与表达规则

## 1. 正文服务于问题，不展示内部工具

内部可以使用分类、路由、检查表和结构化记号，但正文默认只保留：

- 对象和结果；
- 已知事实；
- 连续因果；
- 方案与依据；
- 证据边界；
- 用户需要的行动或判断。

避免写：

- “本次问题类型是……”；
- “本文选择形成前基线……”；
- “主体 S、目标 O、缺口 G……”；
- “下面按照第一性原理框架……”；
- “这一段的推理逻辑是……”。

除非用户明确要求查看分析方法。

用户需要文章、报告或完整方案时，正文还应在标题之后尽快写出文章契约中的读者可见问题。它由核心问题生成，只负责说明本文回答什么；内部完整分析任务、支撑问题、必须覆盖项和证据边界不能被拼成一个长问句。读者可见问题也不能被宽泛主题、文章目的或已经得出的结论代替。

## 2. 先判断交付形式

同一份分析可以有不同交付形式，不能默认都写成长文。

- 用户只问一个判断、原因或下一步：直接回答。
- 用户要求比较：围绕评价标准组织结论。
- 用户要求清单、步骤或方案：按依赖顺序输出行动。
- 用户要求文章、报告、技术说明或完整方案：完成分析后，先形成分析定稿和文章契约，再使用 `references/core/06-文章成稿与压缩.md` 整理成稿。

交付形式只改变信息选择、排列方式和展开程度，不改变事实、因果和不确定性。

## 3. 结构由问题决定

### 定义与分类

可以使用：

1. 简洁定义；
2. 必要属性；
3. 排除边界；
4. 相邻概念；
5. 例子与反例。

### 解释结果

可以使用：

1. 要解释的结果；
2. 结果前已有条件；
3. 长期条件与直接触发；
4. 中间作用过程；
5. 维持、放大和替代解释；
6. 证据与边界。

### 达成目标

可以使用：

1. 目标与完成标准；
2. 目标成立的必要条件；
3. 当前情况和关键差距；
4. 路径与因果依据；
5. 取舍；
6. 执行、验证和调整。

### 判断与选择

可以使用：

1. 目标和评价标准；
2. 关键事实与未知；
3. 各选项对标准的影响；
4. 不同偏好下的结论；
5. 需要进一步验证的信息。

不为了统一格式强制所有输出使用固定三个标题。

对目的型技术、产品、制度和完整行动方案，默认在“要分析的问题”之后继续显式保留“最终目的—当前状态与要解决的问题—采用的方案”。这些节点承担不同职责，不能被有效信息密度或压缩要求删除。对不承载明确目的的对象，只保留读者可见问题，并使用与对象性质匹配的后续结构。

## 4. 分析先证明，呈现可以先给结论

分析时，每项方案必须由已经成立的问题推出，不能先选模块或热门方法，再倒推理由。这个要求约束结论怎样成立，不要求读者先读完全部解释才能看到结论。

例如，内部先建立：

```text
任务要求发生真实外部变化
→ 单纯生成文本不能完成
→ 因此需要受控的环境操作和结果反馈能力
→ 再说明可以怎样实现
```

不能先认定“系统需要工具调用、MCP、沙箱和状态机”，再为固定答案补理由。

结论已经成立后，可以在对应小节先直接说明方案的职责，再解释它怎样补足缺失条件。局部结论先行不改变全文“最终目的—当前状态与要解决的问题—采用的方案”的主链，也不把全部机制提前放进开头。

专业术语、模块和字段应在它第一次成为当前因果问题的必要答案时出现。属于某个结构，不等于需要在第一次介绍该结构时全部展开。

## 5. 每个要点先说准一个结论

本节是局部结论选择与表达的统一规则。文章成稿和写作规则卡沿用本节，不另设相反的顺序或字数要求。

### 先确定当前要点回答什么

每个有独立信息的章节、段落或列表项，先确定它当前承担的问题，再选择一个主要新结论。这里只选择分析定稿已经支持的内容；发现缺少依据时，返回分析阶段修复，不在写作时补造结论。

- **定义、定位**：它是哪一类东西，主要承担什么职责；只保留区分当前对象所必需的基础或范围。
- **最终目的**：目标求解型写希望获得的外部结果；原理还原型可以先写对象稳定角色或目标状态。完成标准另行说明。
- **当前问题**：哪个必要条件尚未满足，具体妨碍什么结果；不提前命名解法。
- **原因解释**：什么因素通过什么作用影响结果；候选原因仍保留候选性质。
- **机制说明**：谁做什么，改变了什么；实现清单不能替代主要作用。
- **判断、建议**：在什么条件下，应怎样判断或行动；证据不足时直接说明不能确定什么。

这些是选择重点的依据，不是固定句式或要求额外展示的问题清单。父要点建立总关系，子要点回答自己的分支问题。相关信息不等于当前位置的重点信息。

### 结论必须是说清具体判断的完整陈述句

大小结论都应直接陈述对象的类别、关系、作用、结果或成立条件。读者在已经说明的对象范围内，不读后面的解释，也应知道当前要点具体得出了什么判断。允许沿用清楚的上下文，不要求每句重复全文背景。

语法完整还不够。“验证本身也有边界”虽是陈述句，却没有说出边界在哪里；“两种设计强度不同”没有说出具体差异；“停止原因需要与成功分开”只提出区分要求。这些句子可以是过渡语，但不能承担主要结论。名词标签、动作口号、同义反复和仅为后文铺垫的事实也不能替代结论。

比较要说出差异，分类要说出分法，边界要说出限制，机制要说出实际作用。需要读者继续问“具体是什么、怎样不同、分成什么、限制在哪里”才能拿到主答案时，应把已经成立的答案移到结论句中。读者继续追问“为什么成立、依据是什么、如何实现”则正常，这些由解释承担。

结论陈述对象本身，不向读者发出“让……”“区分……”“关注……”等空泛指令。行动建议可以使用“应当、需要”，但必须说清谁采取什么具体行动；用户明确要求的操作步骤仍可用祈使句。否定、条件和不确定判断也是陈述句，只要直接给出了有依据的答案，不强行改成肯定或无条件断言。

### 用最少的必要信息直接回答

优先用一句完整、准确、直接的话给出主要结论。先从当前要点的全部已确认内容中选出主要关系，再成句；不要随手截取解释的第一句当结论。短而宽泛、语法完整但没有具体答案，都需要重写。

决定对象范围、因果方向、成立条件或确定性的限定必须保留；已经由相邻上下文明确的范围无需反复声明。不能为了短，把“某类对象”扩大成“所有对象”，把“可能”改成“必然”，或把一种实现写成定义。

依据、过程、实现和例子放在后面，按需要展开。不要用多层修饰和并列，把定义、目的、原因、机制与验收同时压进一句话；也不把必要术语换成含糊的大白话。一个紧密的比较可以有两个分句；多个独立判断则拆开，不追求固定句数或字数。

### 先写结论，再决定是否强调

先不带格式写出结论，检查语义是否完整，再决定是否用标题或粗体强调。加粗不会使普通句子自动成为结论，也不要求每段都加粗首句。

承担结论的内容标题、段首句和列表项遵守同一标准。标题已经完整表达结论时，正文直接解释，不换词重复；标题只说明主题或结构职责时，由首句给出结论。选择加粗时，应保留完整判断，不只加粗“有边界”“需要区分”等半句话，再把真正答案留在普通正文中。

读者可见问题和“最终目的”等固定结构标题仍负责导航，不强行改成答案。仅说明材料类别的“例子”“执行步骤”等标签也不冒充结论。结论需要少量前提才能避免误解时，可以先交代前提，不强制所有句子采用相同顺序。

### 一句话已经完成职责时停止

一句话已经完整回答当前要点，就在这里结束。复杂要点继续说明必要事实、因果和边界；不能用“结论先行”把完整文章改成只有摘要，也不能为了显得详细给简单要点补解释。

停止前先检查答案是否已经说全。“还有边界”“需要分别判断”等未给出实质答案的短句不能触发停止条件。若完整陈述需要的信息尚未得到证明，应说明具体未知或退回分析，不能自行补出答案。

### 句子与段落

一个句子以一个主要新结论或主要关系为中心。若一句话同时要求读者接受多个可以独立成立的结论，优先拆开，并保留“因此、但、只有、同时”等真实关系。

若多个事实或条件本来并行成立，可以使用并列、列表或表格。只有完整推演已经证明先后依赖时，才按因果顺序改写，不能为了行文顺滑制造新的因果。

一个段落围绕一个主要新结论展开。支撑同一结论的相邻句留在本段；开始新的独立问题时再换段。独立小点可以由一句话完成，不能据此把一条连续因果机械拆成多段，也不为每句话增加标题。

## 6. 普通、具体、稳定的语言

能用“谁做什么，改变了什么”表达时，优先写清主体、动作和状态变化。

优先写：

- “系统把当前进度保存下来，下次从这里继续”；
- “运行时读取文件并把结果返回模型”；
- “权限层在执行前检查路径和命令”；
- “测试失败后，错误信息进入下一轮判断”。

少写：

- “进行状态持久化能力建设”；
- “实现执行闭环的体系化支撑”；
- 连续使用“能力、机制、体系、层面、赋能”等抽象名词包装动作。

专业术语确实提高准确性时：

1. 先用普通语言说明它在当前过程里做什么；
2. 再给出术语；
3. 后文保持同一名称，不为追求变化替换多个俗称。

## 7. 控制绝对化语言

谨慎使用：

- 必然；
- 绝对；
- 所有人；
- 任何情况；
- 完美；
- 唯一；
- 本质上都是；
- 彻底解决。

只有逻辑定义、数学命题或明确约束确实支持时才使用，并说明范围。

## 8. 追求有效信息密度

目标不是单位字数塞入最多概念，而是让读者以较低理解成本，获得尽可能多的正确、可用信息。

这里的有效信息包括：

- 会改变结论的事实；
- 不可省略的因果关系；
- 重要边界和区别；
- 真正影响判断或行动的步骤；
- 用户要求掌握的机制和取舍。

理解成本包括：

- 需要回读才能确认主体、指代或关系；
- 一处同时引入过多新概念和新关系；
- 读者必须自行补全被省略的因果；
- 抽象名词、复杂句法或无关细节造成误解；
- 例子和修辞本身又需要额外解释。

因此：

- **简洁**：删除不影响理解、判断或行动的内容。
- **直白**：尽快写出主体、动作、结果和当前结论。
- **直接**：不让元叙述、铺垫和修辞挡在核心信息前。
- **信息密度高**：每段持续增加有效信息，不重复已经建立的内容。
- **不密**：每个局部只要求读者处理有限的新关系，并按真实依赖展开。
- **准确**：成文不能改变推演中的事实、因果方向、成立条件和不确定性。

高信息密度不等于句子都短，也不等于段落都长。句子和段落的长度应服从当前关系是否已经讲清。

## 9. 先具体化，再选择辅助材料

抽象内容难以理解时，按以下顺序处理：

```text
准确的字面因果
→ 具体主体、动作和状态变化
→ 一个代表性真实例子
→ 必要时使用局部类比或比喻
```

示例只有在完成至少一项任务时保留：

- 让抽象机制可以观察；
- 串联多个关键因果；
- 区分容易混淆的概念；
- 展示适用边界；
- 帮助读者检验是否理解。

表格适合横向比较；代码适合展示接口、关键状态或难以用文字说清的执行流。它们不能只是把正文换一种形式再重复一次。

类比或比喻只有在比直接解释更短、更清楚，且不会带入错误属性时使用。使用后要回到字面机制，不能让意象取代事实和因果。

## 10. 文章定位、读者与叙述口吻

文章的目标读者默认是当前提出问题的人。读者视角通过选择其需要的信息、控制解释深度和安排阅读顺序体现，不通过暴露生成上下文体现。技术原理、系统说明和一般报告默认使用中性、自包含的说明口吻，不把读者称为“用户”，不写“用户当前材料”“用户此前提到”“你的求职材料”“本轮对话中”等内容。个人行动建议确有必要时可以使用“你”；只有用户明确要求以自己的口吻发表时才使用“我”。全文视角保持一致。

有效信息密度是成稿质量指标，不是文章定位。文章先明确类型、读者任务、职责范围和范围外内容，再决定哪些信息进入主文。

## 11. 输出前语言检查

- 标题之后是否尽快出现简短、直接的读者可见问题，而不是内部完整分析任务或答案目录？
- 目的结构适用时，最终目的、当前状态与要解决的问题、采用的方案是否仍然可见？
- 文章类型、读者任务和职责范围是否保持稳定？
- 是否出现“用户当前材料”等生成上下文，或在“我、你、用户”之间无理由切换？
- 核心问题或结论是否尽快出现？
- 每个大小结论是否用完整陈述直接回答当前问题，而非标签、口号、同义反复或铺垫？
- 暂时隐藏后文解释和强调格式后，是否仍能知道具体判断、差异或边界？
- 结论是否可见，标题与首句是否避免重复，是否误把每段首句自动加粗？
- 一句话已完整回答时是否停止，复杂要点是否仍保留必要解释？
- 是否出现读者无法理解的内部黑话？
- 是否用夸张词代替证据和机制？
- 是否把推断写成事实？
- 是否把个人偏好写成客观结论？
- 分析是否先认定答案再倒推理由，而不是先证明后呈现？
- 一句话是否承担多个独立结论？
- 已被证明的依赖是否被压成名词清单？
- 是否为了顺滑制造了原推演没有的因果？
- 每段是否围绕一个主要新结论并完成必要解释？
- 是否能把抽象名词还原为明确主体和动作？
- 同一概念是否保持同一名称？
- 示例、表格、代码或比喻是否确实降低理解成本？
- 是否有两段表达同一个结论，只是换了措辞？
- 删除内容后，必要因果桥梁、范围与限定是否仍然存在？
