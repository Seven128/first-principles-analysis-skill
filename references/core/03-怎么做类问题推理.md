# 怎么做类问题推理

## 1. 目标

“怎么做”类分析研究：一个主体怎样从当前真实情况走到尚未达到的目标。

它不是经验清单，也不是直接推荐热门方案。正确顺序是：

```text
目标成立必须发生什么
→ 当前已经具备什么
→ 还缺什么
→ 哪些路径能补足
→ 在当前约束下怎样选择和执行
```

## 2. 第一步：补全目标

至少明确：

- 谁要达到目标；
- 目标具体是什么；
- 完成到什么程度算成功；
- 时间范围；
- 不能突破的限制；
- 用户真正优先的结果。

例如“我要赚很多钱”仍然不完整。可能需要区分：

- 一次性还是重复收入；
- 收入金额还是增长速度；
- 时间要求；
- 可投入资金、时间和技能；
- 可承受波动与损失。

没有信息时使用条件分支，不编造个人情况。

## 3. 第二步：从结果倒推必要条件

问：

> 这个结果要成为事实，客观上必须发生什么？

例如“获得收入”：

```text
钱必须从某个持有者或分配机制流向主体
→ 对方必须有支付或分配能力
→ 必须满足让对方愿意或必须支付的条件
→ 主体必须能够接触对方并完成交换或分配流程
→ 实际获得的结果必须符合主体接受的成本和限制
```

这里尚未预设做产品、打工、投资或流量变现。

必要条件必须说明为什么与目标有关，不能从已有方案模块反推。

## 4. 第三步：检查当前情况

分别检查：

- 已有能力；
- 已有资源；
- 已有渠道和关系；
- 已知限制；
- 当前行为和执行状态；
- 外部环境；
- 缺失或未知信息。

区分：

- **没有条件**：当前确实不具备；
- **条件不稳定**：偶尔具备，无法可靠复现；
- **条件未知**：材料不足，不能判断；
- **条件已经具备但没有连接起来**：问题在流程或协作。

## 5. 第四步：找出真正的差距

差距应处于能够指导方案的层级。

过粗：

- 能力不足；
- 竞争激烈；
- 没有资源。

过细：

- 必须马上开某个平台账号；
- 必须使用某个具体框架；
- 必须做某种热门项目。

合适表达：

- 当前没有稳定触达目标付费者的渠道；
- 能力存在，但无法被招聘方验证；
- 产品能够解决问题，但首次使用成本高于用户预期收益；
- 方案依赖一个主体无法控制的外部平台规则。

## 6. 第五步：区分控制程度

### 能够直接控制

例如学习、作品、产品设计、沟通、执行频率、价格实验。

### 部分能够影响

例如他人信任、渠道曝光、合作关系、企业决策。

### 难以控制

例如宏观需求、政策变化、竞争者行为、随机事件。

方案优先围绕可控制和可影响因素，但不能假装不可控因素不存在。对不可控因素设计：

- 监测；
- 情景分支；
- 缓冲；
- 止损或退出条件；
- 替代路径。

## 7. 第六步：生成多条路径

路径应从必要条件和资源来源推出，而不是从流行做法罗列。

每条路径至少回答：

```text
它补足哪个条件？
它通过什么过程产生结果？
主体需要投入什么？
依赖谁或什么？
关键失败点在哪里？
需要什么事实验证？
```

若路径互不排斥，说明可以组合；若资源冲突，说明取舍。

## 8. 第七步：中性比较路径

根据用户明确目标，比较：

- 可能结果；
- 达成概率；
- 所需时间；
- 资金、精力和机会成本；
- 收益波动；
- 可逆性；
- 所需能力；
- 对外部平台、组织或个人的依赖；
- 法律、规则和安全限制；
- 信息要求与验证成本。

不得默认：

- 长期优于短期；
- 稳定优于高波动；
- 可持续优于一次性；
- 高增长优于利润；
- 自主创业优于就业；
- 更复杂的系统优于简单行动。

若评价标准不同，给出不同结论。

## 9. 第八步：安排执行顺序

按依赖关系安排，而不是按文章标题顺序。

通常先处理：

1. 会使整条路径不成立的事实假设；
2. 成本低、能够快速获得信息的验证；
3. 多条路径共同依赖的基础条件；
4. 不可逆或高成本决策之前的试验；
5. 正式扩张和优化。

方案可以分成：

- 最小验证；
- 最小可行闭环；
- 扩大规模；
- 性能、成本和风险优化。

但只有当前问题确实需要时才使用这些阶段，不机械套用。

## 10. 第九步：建立反馈和调整

行动不是一次性答案。至少明确：

- 用什么结果判断路径有效；
- 在什么时间检查；
- 哪些指标只是过程信号，哪些是真实结果；
- 哪个假设失败后应调整；
- 什么情况继续、暂停、切换或退出。

例如获客中，曝光不是最终用户增长；注册也不等于持续使用。必须选择与目标一致的结果指标。

## 11. 输出最小闭环

一份合格行动分析至少应说明：

```text
目标是什么、怎样算完成
→ 目标成立必须具备哪些条件
→ 当前已经有什么、还缺什么
→ 有哪些可行路径及其因果依据
→ 各路径的结果、成本、依赖和限制
→ 先验证什么、再做什么
→ 怎样判断并调整
```
