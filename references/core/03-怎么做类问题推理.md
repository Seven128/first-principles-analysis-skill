# 怎么做类问题推理

## 1. 目标

“怎么做”类分析研究：一个主体怎样从当前真实情况走到尚未达到的目标。

它不是经验清单，也不是直接推荐热门方案。正确顺序是：

```text
目标成立必须发生什么
→ 当前已经具备什么
→ 还缺什么
→ 哪些路径能补足
→ 在当前约束下怎样选择和执行
```

## 2. 第一步：补全目标

至少明确：

- 谁要达到目标；
- 目标具体是什么；
- 完成到什么程度算成功；
- 时间范围；
- 不能突破的限制；
- 用户真正优先的结果。

例如“我要赚很多钱”仍然不完整。可能需要区分：

- 一次性还是重复收入；
- 收入金额还是增长速度；
- 时间要求；
- 可投入资金、时间和技能；
- 可承受波动与损失。

没有信息时使用条件分支，不编造个人情况。

## 3. 第二步：从结果倒推候选必要条件

问：

> 这个结果要成为事实，客观上必须发生什么？

例如“获得收入”：

```text
钱必须从某个持有者或分配机制流向主体
→ 对方必须有支付或分配能力
→ 必须满足让对方愿意或必须支付的条件
→ 主体必须能够接触对方并完成交换或分配流程
→ 实际获得的结果必须符合主体接受的成本和限制
```

这里尚未预设做产品、打工、投资或流量变现。

必要条件必须说明为什么与目标有关，不能从已有方案模块反推。此时得到的仍是候选必要条件；后续还要检查没有该条件时目标是否真的不能成立，以及是否把一种具体实现误写成了必要条件。

## 4. 第三步：检查当前情况

分别检查：

- 已有能力；
- 已有资源；
- 已有渠道和关系；
- 已知限制；
- 当前行为和执行状态；
- 外部环境；
- 缺失或未知信息。

区分：

- **没有条件**：当前确实不具备；
- **条件不稳定**：偶尔具备，无法可靠复现；
- **条件未知**：材料不足，不能判断；
- **条件已经具备但没有连接起来**：问题在流程或协作。

## 5. 第四步：找出真正的差距

差距应处于能够指导方案的层级。

过粗：

- 能力不足；
- 竞争激烈；
- 没有资源。

过细：

- 必须马上开某个平台账号；
- 必须使用某个具体框架；
- 必须做某种热门项目。

合适表达：

- 当前没有稳定触达目标付费者的渠道；
- 能力存在，但无法被招聘方验证；
- 产品能够解决问题，但首次使用成本高于用户预期收益；
- 方案依赖一个主体无法控制的外部平台规则。

## 6. 第五步：区分控制程度

### 能够直接控制

例如学习、作品、产品设计、沟通、执行频率、价格实验。

### 部分能够影响

例如他人信任、渠道曝光、合作关系、企业决策。

### 难以控制

例如宏观需求、政策变化、竞争者行为、随机事件。

方案优先围绕可控制和可影响因素，但不能假装不可控因素不存在。对不可控因素设计：

- 监测；
- 情景分支；
- 缓冲；
- 止损或退出条件；
- 替代路径。

## 7. 第六步：生成多条路径

路径应从必要条件和资源来源推出，而不是从流行做法罗列。

每条路径至少回答：

```text
它补足哪个条件？
它通过什么过程产生结果？
主体需要投入什么？
依赖谁或什么？
关键失败点在哪里？
需要什么事实验证？
```

若路径互不排斥，说明可以组合；若资源冲突，说明取舍。

## 8. 第七步：按问题需要补强路径生成

补强方法只能扩展或检验由目标、事实、差距推出的路径，不能跳过主链直接给热门方案。简单行动问题已经有足够路径时，不为展示方法而强行加入历史研究、跨领域案例或多视角讨论。

### 8.1 双遍推导：先重新推导，再审查现有方案

当当前系统已经堆积多层补丁、路径依赖较强，或者用户明确希望检查是否需要重构时，可以执行双遍推导。

第一遍暂时隐藏现有方案，只保留：

```text
目标与完成标准
→ 已确认事实
→ 无法忽略的约束与可用资源
→ 候选必要条件
→ 可满足条件的上位设计方向
```

第二遍重新放回现有方案，逐项检查：

- 它补足了哪个已经证明的条件；
- 它是当前环境下仍然合理的实现，还是早期约束留下的历史取舍；
- 它是否只压住表面症状，没有改变根问题；
- 它是否在补偿另一项设计带来的副作用；
- 当前条件变化后，它是否仍有正向作用；
- 是否存在成本更低或风险更小的替代路径。

重置的是推理起点，不是预设要推翻现有实现。最后应比较保留、局部修复、替换部分机制和重新构建等路径的收益、迁移成本、兼容风险、可逆性与验证难度，不默认推倒重来。

### 8.2 跨领域借解：用结构相似生成候选机制

当本领域常见路径都受限，或者需要扩展方案空间时，可以先去掉行业术语，把问题还原为：

```text
有哪些主体
→ 什么资源或状态在流动
→ 存在哪些硬约束、激励、反馈和延迟
→ 当前核心矛盾是什么
→ 普通解法为什么失效
```

再从距离较远的领域寻找具有相似作用结构的问题，逐项检查：

- 对方原本要改变什么结果；
- 使用的机制通过什么过程起作用；
- 与当前问题对应的主体、资源、约束和反馈是什么；
- 哪些条件能够映射；
- 哪些环境差异不能映射；
- 移植后最可能在哪里失效。

跨领域类比只能生成候选路径，不能证明路径在当前场景有效。候选机制返回当前问题后，仍要重新经过必要条件、因果过程、成本、规则和证据校验。

### 8.3 多视角交叉审查：让互补变量共同修正方案

当方案同时受技术可行性、用户选择、组织激励、资源分配、法律规则或执行成本影响时，可以选择若干互补分析视角。视角数量服从问题，不固定为三个，也不模拟真实专家的个人观点。

每个视角分别提出：

- 它认为最关键的差距；
- 能补足该差距的路径；
- 其他视角容易忽略的失败条件；
- 哪项新证据会使其调整建议。

综合时先确定共同事实，再找出分歧背后的不同假设和评价标准，最后回到同一目标链比较路径。不能把多份视角意见直接并列成没有选择依据的方案清单。

### 8.4 历史信息只在路径依赖会改变行动时进入

过去的选择、累积能力、迁移成本和历史包袱只有在它们会改变当前可行路径、实施顺序或退出成本时才进入行动分析。此时使用 `references/core/02-为什么类问题推理.md` 中的历史纵轴补足事实，再回到当前目标与差距。用户只需要从零设计一条路径时，不先写一段对象发展史。

## 9. 第八步：校验必要条件与路径节点

按照 `references/core/04a-关键推理节点反向校验.md` 检查直接决定方案的条件和路径。

### 检查候选必要条件

问：

```text
没有这个条件时，目标是否仍可能通过其他方式成立？
```

若答案是可能，该项就不是必要条件，通常只是：

- 一种具体实现；
- 一条可选路径；
- 一个促进因素；
- 更高层必要条件在当前场景中的一种表现。

此时应上提真正必要的条件，并把现有做法与替代路径并列。例如，目标可能需要“可恢复且经过验证的独立数据副本”，而不必预先写成“必须使用主从复制”。

### 检查路径是否足以产生结果

问：

```text
即使采用这条路径，目标仍可能因为什么不成立？
```

若存在这种情况，应补充：

- 路径依赖的前置条件；
- 中间作用过程；
- 外部主体是否配合；
- 会抵消效果的限制；
- 失败后的替代路径和退出条件。

不能把“采用方案”直接等同于“达到目标”。

### 检查关系强度

若路径只能提高成功概率，就写成概率或期望影响，并说明比较条件。一次失败不能证明路径完全无效，一次成功也不能证明路径必然有效。

校验后，根据结果补条件、增加替代路径、降低结论强度、缩小范围或删除节点，再进入路径比较。

## 10. 第九步：中性比较路径

根据用户明确目标，比较：

- 可能结果；
- 达成概率；
- 所需时间；
- 资金、精力和机会成本；
- 收益波动；
- 可逆性；
- 所需能力；
- 对外部平台、组织或个人的依赖；
- 法律、规则和安全限制；
- 信息要求与验证成本。

不得默认：

- 长期优于短期；
- 稳定优于高波动；
- 可持续优于一次性；
- 高增长优于利润；
- 自主创业优于就业；
- 更复杂的系统优于简单行动。

若评价标准不同，给出不同结论。

## 11. 第十步：选择信息价值最高的最小实验

当主要分歧仍来自未经验证的事实或路径假设时，继续讨论不一定增加有效信息。先列出会改变路径选择、实施范围或继续条件的关键假设，再判断：

```text
若该假设被证伪，会淘汰多少候选路径？
会不会改变高成本或不可逆决定？
验证结果是否能在可接受周期内获得？
```

优先验证对最终选择影响大、当前不确定性高、验证成本低的假设。实验应尽量低成本、可逆、短周期，但周期和假设数量由问题决定，不固定为三项或七天。

每个最小实验至少说明：

- 具体要做什么；
- 需要投入的时间、资金、权限和协作资源；
- 观察与目标直接相关的结果指标；
- 什么结果支持继续或扩大；
- 什么结果提示暂停、切换或退出；
- 实验结束后新增了什么信息，下一项不确定性是什么。

实验只是获得信息的手段。曝光、点击、完成一次操作等过程指标，不能在没有证明关系时替代最终目标结果。

## 12. 第十一步：安排执行顺序

按依赖关系安排，而不是按文章标题顺序。

通常先处理：

1. 会使整条路径不成立的事实假设；
2. 成本低、能够快速获得信息的验证；
3. 多条路径共同依赖的基础条件；
4. 不可逆或高成本决策之前的试验；
5. 正式扩张和优化。

方案可以分成：

- 最小验证；
- 最小可行闭环；
- 扩大规模；
- 性能、成本和风险优化。

但只有当前问题确实需要时才使用这些阶段，不机械套用。

## 13. 第十二步：建立反馈和调整

行动不是一次性答案。至少明确：

- 用什么结果判断路径有效；
- 在什么时间检查；
- 哪些指标只是过程信号，哪些是真实结果；
- 哪个假设失败后应调整；
- 什么情况继续、暂停、切换或退出。

例如获客中，曝光不是最终用户增长；注册也不等于持续使用。必须选择与目标一致的结果指标。

## 14. 输出最小闭环

一份合格行动分析至少应说明：

```text
目标是什么、怎样算完成
→ 目标成立必须具备哪些条件
→ 当前已经有什么、还缺什么
→ 有哪些可行路径及其因果依据
→ 关键条件和路径经校验后补充了哪些前提或替代方案
→ 各路径的结果、成本、依赖和限制
→ 先验证什么、再做什么
→ 怎样判断并调整
```

双遍推导、跨领域借解、多视角审查和历史信息只在本题实际启用时贡献候选路径、取舍与边界；最终输出不展示无关的方法清单。
