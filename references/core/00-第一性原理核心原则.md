# 第一性原理核心原则

## 1. 定义

第一性原理分析，是暂时不把未经重新验证的经验、惯例、类比、权威结论和现成方案当作必然答案，回到当前问题中能够确认的事实、定义、限制和因果关系，再从这些基础条件重新推出解释、判断或行动方案。

“放下经验”不等于删除已有知识。经验可以提供候选方向，但必须重新检查：

- 是否适用于当前对象；
- 是否处于相似环境；
- 是否依赖当前并不存在的条件；
- 是否只是历史上的常见做法，而不是逻辑上唯一的做法；
- 是否存在反例或失效范围。

## 2. 核心标准

结论必须能够回答：

```text
它依赖哪些已知事实？
这些事实怎样产生下一步变化？
为什么不是别的结果？
还有哪些解释也可能成立？
需要什么证据继续确认？
```

分析应能够正向推导：

```text
事实与限制
→ 必要条件
→ 原因、问题或差距
→ 机制、行为或方案
→ 结果
```

也应能够反向追溯：

```text
这个结论或方案为什么存在
→ 它处理了什么原因、问题或差距
→ 该原因或差距破坏了什么必要条件
→ 该条件为什么与最终结果有关
```

## 3. 经验的正确位置

经验、案例、行业规律和已有结论只可以作为：

- 需要优先检查的方向；
- 可能成立的解释；
- 方案候选；
- 反例来源；
- 对推理结果的外部校验。

它们不能替代当前问题的事实与证明。

调用已知经验时，先区分三种材料：主体指南中的检查方法用于提出问题和收集证据；结论卡中的条件性命题用于生成候选解释；当前资料中的事实才可以在核实范围后支持本题判断。方法本身有效，不代表按它提出的假设已经成立。产品发现和商业化合规等场景方法只在命中问题时读取，不把它们变成每次分析的固定步骤。

### 通用规则与场景经验的边界

通用核心只规定跨对象仍成立的推理操作，例如分清事实与假设、检查必要性、保持证据与结论强度一致。依赖特定主体、业务、地区、工具或交付体裁的做法，放在相应主体指南、结论卡或写作适配中，并写清触发条件和失效范围。

新增经验前，先问现有规则是否已经完成同一任务。只保留能补上独立遗漏、改变证据质量或改善判断的方法，不因名称、作者或框架不同再加一遍流程。外部 skill 的星标和点赞只用于筛选阅读来源，不证明其结论正确；版本、来源和采用边界放在迭代记录中，日常运行不必重新研究整个仓库。

抽取核心时，替换项目名、平台和实现后检查规则是否仍成立。只在特定环境成立的部分继续保留为有标签的场景经验，不能为追求通用而删掉必要条件，也不能把单个案例里的模块、阈值、审批或发布流程升为普遍要求。

## 4. 必要条件、充分条件和具体实现

必须区分：

- **必要条件**：缺少后，目标或结果无法成立；
- **充分条件**：单独满足后，足以使结果成立；
- **促进条件**：会提高概率或程度，但不是绝对必需；
- **具体实现**：满足某项条件的一种办法，不一定唯一；
- **伴随现象**：与结果同时出现，但不一定促成结果。

第一性原理经常能推出“需要某类能力或条件”，但通常不能仅凭逻辑证明“当前已有实现是唯一选择”。

## 5. 因果纪律

不得把以下内容直接当作因果：

- A 先发生，B 后发生；
- A 与 B 同时变化；
- 多数案例中 A 和 B 一起出现；
- 不能因为当前系统包含 A，就认定 A 必然是系统形成的原因；
- 不能因为某人从行为中获益，就认定获益必然是他的真实动机；
- 某种解释听起来合理，所以它已经得到证实。

至少要说明：

```text
A 通过什么过程影响 B？
缺少 A 时，B 是否仍可能出现？
是否存在共同原因 C？
是否有其他解释也能产生 B？
当前证据能支持到什么程度？
```

## 6. 客观不等于没有目标

行动和选择问题通常包含评价标准。例如“赚钱更多”“风险更低”“尽快完成”本身就是用户选择的目标。

客观分析要求的是：

- 不偷偷加入用户没有选择的标准；
- 不把个人偏好写成事实；
- 不默认长期优于短期、稳定优于波动、持续优于一次性；
- 明确不同目标下结论可能不同；
- 法律、平台规则、物理限制和安全边界作为客观约束说明，而不是道德标签。

## 7. 语言原则

使用普通、准确的语言。内部可以用结构化符号检查推理，正文不应依赖黑话才能理解。

优先写：

- “分析从什么状态开始”；
- “当时已经具备什么”；
- “距离结果还缺什么条件”；
- “采用这种做法后又出现什么问题”。

避免为了显得专业而使用“基线、顶层缺口、物理降维、绝对、完美、跃迁”等词。专业术语确实能提高准确性时，应在第一次出现时用普通语言解释。
