# 为什么类问题推理

## 1. 目标

“为什么”类分析解释一个已经存在的结果是怎样形成的。结果可以是：

- 技术或制度形成当前结构；
- 某个人产生情绪、作出选择或没有行动；
- 组织作出决策；
- 市场价格、资源或参与者行为发生变化；
- 自然系统出现某种现象。

它不是为一个现成答案补理由，而是从结果出现前的条件出发，逐步检查哪些变化足以解释结果。

## 2. 第一步：精确定义要解释的结果

避免分析模糊的“为什么这样”。明确：

- 具体发生了什么；
- 在什么时间和环境发生；
- 结果表现在哪些可观察事实上；
- 哪些只是他人的描述或评价；
- 需要解释“出现”“维持”“增强”“重复”还是“形成当前结构”。

不同结果可能需要不同原因。例如“为什么第一次生气”与“为什么长期容易生气”不是同一个问题。

## 3. 第二步：判断结果的性质

### 3.1 人为设计的结果

如技术、产品、协议、制度。

重点检查：

- 它承担什么任务；
- 原有能力为什么不够；
- 缺少什么条件；
- 当前机制怎样补足条件；
- 新机制带来什么后续问题；
- 哪些是逻辑需要，哪些是历史取舍。

### 3.2 有意识行为或选择

如合作、拒绝、辞职、隐瞒、分配项目。

重点检查：

- 对方认为有哪些选择；
- 每个选择预期带来什么收益、损失和风险；
- 对方掌握什么信息；
- 规则、关系和资源怎样影响选择；
- 行为是否真的经过明确权衡。

### 3.3 自动或半自动反应

如愤怒、恐惧、回避、习惯、冲动。

重点检查：

- 发生了什么刺激；
- 主体怎样感知和解释；
- 哪项预期、需要、身份、边界或控制感受到影响；
- 生理状态、长期压力和习惯是否放大反应；
- 是否存在无意识过程。

### 3.4 群体共同形成的结果

如组织文化、价格、行业周期、舆论。

重点检查：

- 不同参与者分别依据什么信息行动；
- 个体行动怎样相互影响；
- 是否存在反馈、延迟和资源限制；
- 群体结果是否与任何单个参与者的目标不同。

### 3.5 自然形成的结果

如生物、物理和生态现象。

重点检查物质、能量、信息、局部规则、环境约束、反馈和选择过程。不得把自然现象拟人化为“为了某目的而设计”。

## 4. 第三步：拆分原因层次

至少区分以下层次。

### 长期条件

让结果成为可能或更容易出现的背景，例如：

- 系统结构；
- 长期激励；
- 资源分布；
- 习惯与技能；
- 性格和长期压力；
- 技术限制；
- 环境规律。

### 直接触发

使结果在此时出现的事件，例如：

- 一次冲突；
- 一个需求变化；
- 一次价格信号；
- 一项新限制；
- 一个输入或故障。

### 中间作用过程

从条件和触发到结果之间发生了什么。必须尽量写清：

```text
输入或事件
→ 主体状态、判断或资源发生什么变化
→ 该变化为什么推动下一步
→ 结果怎样形成
```

### 维持因素

解释结果为什么持续、重复或稳定存在，例如：

- 正反馈；
- 转换成本；
- 权力和资源控制；
- 习惯强化；
- 缺少替代路径；
- 规则持续奖励同类行为。

### 放大和抑制因素

同一原因在不同条件下可能产生不同程度的结果。说明哪些因素会让结果更强、更弱或不发生。

## 5. 第四步：建立候选解释，而不是立即定论

复杂结果通常有多个可能原因。对每个候选解释检查：

```text
它能解释哪些已知事实？
不能解释哪些事实？
需要额外假设什么？
是否存在更简单的解释？
不同解释能否同时成立？
用什么新证据可以区分它们？
```

人的动机、情绪和经历尤其需要保留候选性质。

## 6. 第五步：区分逻辑重建和真实历史

分析人为设计物时，可以通过逻辑说明：

> 为完成某项任务，系统需要某类能力；原有能力缺少它，因此要增加某种机制。

这不自动证明：

> 历史上的设计者当时就是出于这个原因，并按照同样顺序完成设计。

涉及真实设计史、人物意图、版本变化和社会事件时，需要文档、记录或其他历史证据。

## 7. 第六步：机制按依赖关系出现

解释技术和制度时，不能先列完整组成，再逐项寻找理由。

应当写成：

```text
当前任务提出要求
→ 当时已有能力无法满足
→ 缺少某类条件
→ 引入一种机制
→ 机制改变了系统状态
→ 新状态又暴露新的问题
→ 再引入后续机制
```

无依赖关系的机制可以并列，但每一项仍需有独立的问题来源。

## 8. 按问题需要启用补充分析轴

补充分析轴不能替代主因果链。先按前述步骤解释结果，再判断历史、比较、多视角或未来场景是否会实质改变结论。简单定义、当前机制说明、一次具体情绪、普通事实确认和不涉及演化的自然结果，不因为存在这些方法就自动变成历史研究或竞品分析。

### 8.1 历史纵轴：解释真实演化、路径依赖和当前包袱

只有当用户询问真实演进、版本变化、早期选择、关键转折、路径依赖，或者过去形成的能力与约束会改变当前判断时，才展开历史纵轴。

历史纵轴按状态变化组织，不按年份堆资料：

```text
当时要解决的结果
→ 当时已有能力、限制和可见选项
→ 实际发生的选择或事件
→ 直接结果与新状态
→ 沉淀的能力、依赖、迁移成本或包袱
→ 下一次转折
```

对每个重要转折，仍然使用本 Skill 的目的、现状、缺失条件、方案和新状态关系解释；历史纵轴只是把多个真实转折串起来。关键推动者、真实动机和“当时为什么选择这一项”只有在材料支持时才能确认。当前结构能够说明机制今天承担什么作用，不能单独证明历史人物当时的想法。

历史追溯在更早信息不再改变当前解释、判断或行动时停止。用户只问当前运行机制时，不为完整感补一条发展史。

### 8.2 横向对照：用真实差异检查必要性、充分性和选择原因

横向对照只有在比较能够检验因果节点、区分路径或解释真实选择时启用。选择比较对象前先说明它们为什么具有可比性，再从核心问题、目标结果和关键矛盾推出统一维度。

优先使用四类对照：

- **相同目标、不同实现**：检查当前机制是否真是必要条件，还是补足同一上位条件的一条路径；
- **相同机制、不同结果**：检查该机制是否足够，是否还依赖环境、执行质量或其他共同条件；
- **同一对象、不同时间**：检查哪项变化与结果变化同时发生，是否存在更合理的共同原因；
- **选择与放弃行为**：在产品、商业或制度问题中，检查价值、成本、信任、风险和切换条件怎样影响真实选择。

比较维度必须对所有对象使用同一含义，并检查时间、规模、环境和成熟阶段是否相近。横向对照的产物首先是对原因果链的修正，不是为了得到一张内容丰富但不回答问题的表格。

### 8.3 多视角交叉审查：利用分歧发现遗漏变量

当问题同时涉及多类主体、资源、激励、技术可行性或用户选择，单一视角容易漏掉关键变量时，可以选择若干真正互补的分析视角。视角数量由问题决定，不固定为三个，也不需要模拟知名专家或编造人物意见。

每个视角分别说明：

- 它把哪个对象、结果或限制放在中心；
- 它提出什么候选解释；
- 其他视角容易遗漏什么风险；
- 什么新增证据会让它改变判断。

随后只保留共同确认的事实、真正分歧和分歧背后的假设，再回到统一因果链修正节点。多视角输出不能变成几份彼此独立、没有综合裁决的角色发言。

### 8.4 横纵交叉后的未来场景

只有用户需要未来判断，而且历史积累、当前差异与外部条件确实会影响未来时，才继续建立场景：

```text
已经积累的能力与资源
+
路径依赖、迁移成本和历史包袱
+
横向对照中存在的替代路径
+
可能变化的外部条件
→ 条件化的未来路径
→ 每条路径的成立前提、可观察信号与失效信号
```

未来路径数量由真实分支决定，不固定为三条。输出说明“哪些条件出现会提高某条路径的可能性”，不把场景推演写成已经确定的未来事实。

## 9. 第七步：校验关键解释节点

候选因果链形成后，按照 `references/core/04a-关键推理节点反向校验.md` 检查直接支撑结论的节点。先明确该节点声称的是必要条件、充分条件、促进条件、一种实现路径还是伴随关系，再选择对应检查。

对候选关系“条件或原因 A 促成结果 B”，至少检查：

- A 已经存在但 B 没出现时，是否说明 A 不充分、遗漏了共同条件或存在抑制因素；
- A 不存在但 B 仍出现时，是否说明 A 不必要，存在替代原因或替代路径；
- 是否可能是 B 影响 A，或者共同原因 C 同时产生 A 和 B；
- 当前结论是严格命题、概率关系还是历史意图判断，反例能支持到什么程度；
- 相似环境中结果没有出现时，关键差异是什么。

校验失败后，不得保留原节点并只附一句“也可能有例外”。应根据原因补充条件、拆出中间过程、加入替代解释、降低结论强度、缩小范围或删除节点。

反向校验不能在缺乏事实时制造虚构历史，也不能把逻辑上需要某项能力直接写成设计者的真实动机。

## 10. 停止追溯

原因可以无限向前追。满足以下条件时通常可以停止：

- 已经解释当前结果的关键形成过程；
- 继续追溯不会改变本次判断或行动；
- 更深原因缺少证据，只能产生猜测；
- 已经到达当前任务要求的对象层级；
- 用户没有要求讨论更长历史。

例如分析一次愤怒，通常先停在当前感知、预期、需要和处境。只有性格、长期模式或价值观本身需要解释时，才继续追溯成长经历。

## 11. 输出最小闭环

一份合格解释至少应让读者知道：

```text
需要解释的结果是什么
→ 结果出现前已经有什么
→ 哪些条件和触发最关键
→ 它们通过什么过程产生结果
→ 哪些因素维持或改变结果
→ 关键节点经过校验后补充了哪些条件或替代解释
→ 哪些结论是事实，哪些是推断
→ 还有哪些替代解释和证据缺口
```

只有本题实际启用了历史纵轴、横向对照、多视角审查或未来场景时，才把它们产生的有效结论、比较依据和信号写入输出；方法名称和完整检查过程默认不进入正文。
