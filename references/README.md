# References

本目录分为五类材料。

## 1. `core/`：运行时核心规则

每次分析按问题方向读取。这里规定：

- 第一性原理的基本要求；
- 复杂输入怎样分离事实、观点、目标、限制、问题与交付要求；
- 问题怎样建模为核心问题、支撑问题与独立问题；
- 意图怎样根据对象状态、行动主体、用户角色、时间方向和期望交付识别，而不是按问句形式判断；
- 哪些问题承载明确目的，以及最终目的、当前状态、要解决的问题、设计原则、方案与验证怎样形成连续关系；
- 目的结构何时不适用，怎样避免给定义、自然结果、群体涌现和自动情绪虚构目的；
- “为什么”与“怎么做”的具体推理；
- 关键原因、必要条件、方案路径和小结论怎样做反例、反事实、必要充分性、替代路径与因果方向校验；
- 事实、推断、假设和评价标准；
- 通用输出与表达；
- 文章、报告和完整方案怎样从完整推演转换成稿。

`01-问题识别与分类.md` 负责入口问题建模。它先提取候选问题，区分核心、支撑和独立关系，再补全真正用于推演的实际分析问题，之后依据场景选择定义、解释、行动、判断或混合路线。“X 是怎么做的”可能是在问已有对象的实现机制，“我怎样做 X”通常是在问未来行动；疑问词本身不能决定路线。

`01a-目的、现状、问题与方案.md` 在问题结构确定后读取。它先判断对象是否具有明确行动主体、设计任务或用户目标；适用时建立“最终目的与完成标准—当前状态—尚未成立的条件和问题—设计原则—具体方案—验证与边界”，并要求每项方案能够回到一个已证明的问题。不适用时继续使用结果解释、定义或比较结构，避免目的论和固定模板。

`04a-关键推理节点反向校验.md` 在候选节点形成后、正式因果链和文章成稿之前读取。它只校验直接支撑结论或行动选择的关键节点，并要求在发现漏洞后修复条件、范围或结论强度；内部检查表默认不进入最终输出。

`06-文章成稿与压缩.md` 只在需要文章或长篇交付时读取。它负责锁定推演不变量、提取因果主线、生成段落骨架、执行句子变换、控制详细程度并回查保真。它不能恢复已经被节点校验淘汰的强结论，也不能改变入口阶段建立的问题结构和目的结构适用性。

## 2. `writing/`：按长篇任务加载的成文规则

当前包含：

- `00-分析定稿与文章契约.md`：定义分析定稿、文章契约、实际分析问题、文章开头、结构节点保留、成文权限和叙述视角；
- `01-写作规则卡.md`：把直白、不密、具体等要求变成可执行变换；
- `02-文章任务适配.md`：按原理文章、完整方案、决策、经营分析、行为解释和定义任务调整组织方式；
- `03-成文检查.md`：从语言、结构、内容保真和整体阅读四层检查并局部修复；
- `04-信息密度、段落与例子控制.md`：防止一句一段、微型例子泛滥、普通文字代码块化和总结重复，明确默认先用直接语言、必要时再用一个整体例子。

这些规则只改变最终表达，不重新分析事实，也不覆盖 `core/` 中的问题建模、目的结构、因果、节点校验和证据规则。`00-分析定稿与文章契约.md` 在两层之间建立交接边界：写作只接收语义锁定的分析定稿，不直接从原始对话继续推理。默认语气保持平静、中性、直接；个人作者风味不是通用运行时规则。

## 3. `subjects/`：主体指南

按当前问题需要读取。指南提供不同对象应优先检查的变量，不是固定答案。主体判断还用于确认对象是否具有统一目的：人为设计系统和明确行动主体通常可以使用目的结构；自然过程和多主体涌现结果不能因此被拟人化。

## 4. `conclusions/`：通用结论卡

保存过去分析中可复用的候选规律。每条结论都有适用条件、失效边界和证据要求；使用前必须重新验证，并把产生的关键候选节点交给通用节点校验。

## 5. 原始来源与回归材料

- `第一性原理分析逻辑.md`
- `第一性原理分析提示词.md`
- `经验/`
- `回归样例/`

这些文件由 v1 来源材料保留，哈希记录在 `source-manifest.json`。默认不作为当前每次运行时的完整上下文；只有做 Skill 迭代、回归定位或用户明确要求对照时才读取。

`examples/旧案例使用说明.md` 说明旧案例中哪些能力可以学习、哪些表达和结论不能直接复制。复杂输入与意图路由专项案例保存在 `evals/intent-routing-regression-cases.json`，关键节点专项案例保存在 `evals/node-validation-regression-cases.json`，目的结构的适用性与反模板化案例保存在 `evals/purpose-structure-regression-cases.json`，成对成文样本保存在 `evals/writing-style-pairs.json`，段落、例子、代码块与重复控制保存在 `evals/writing-density-regression-cases.json`。这些材料只用于回归和校准，不作为当前问题的事实来源。
