# References

本目录分为五类材料。

## 1. `core/`：运行时核心规则

每次分析按问题方向读取。这里规定：

- 第一性原理的基本要求；
- 问题怎样补全和分类；
- “为什么”与“怎么做”的具体推理；
- 事实、推断、假设和评价标准；
- 通用输出与表达；
- 文章、报告和完整方案怎样从完整推演转换成稿。

`06-文章成稿与压缩.md` 只在需要文章或长篇交付时读取。它负责锁定推演不变量、提取因果主线、生成段落骨架、执行句子变换、控制详细程度并回查保真。

## 2. `writing/`：按长篇任务加载的成文规则

当前包含：

- `01-写作规则卡.md`：把直白、不密、具体等要求变成可执行变换；
- `02-文章任务适配.md`：按原理文章、完整方案、决策、经营分析、行为解释和定义任务调整组织方式；
- `03-成文检查.md`：从语言、结构、内容保真和整体阅读四层检查并局部修复。

这些规则只改变最终表达，不重新分析事实，也不覆盖 `core/` 中的因果和证据规则。默认语气保持平静、中性、直接；个人作者风味不是通用运行时规则。

## 3. `subjects/`：主体指南

按当前问题需要读取。指南提供不同对象应优先检查的变量，不是固定答案。

## 4. `conclusions/`：通用结论卡

保存过去分析中可复用的候选规律。每条结论都有适用条件、失效边界和证据要求；使用前必须重新验证。

## 5. 原始来源与回归材料

- `第一性原理分析逻辑.md`
- `第一性原理分析提示词.md`
- `经验/`
- `回归样例/`

这些文件由 v1 来源材料保留，哈希记录在 `source-manifest.json`。默认不作为 v2 每次运行时的完整上下文；只有做 Skill 迭代、回归定位或用户明确要求对照时才读取。

`examples/旧案例使用说明.md` 说明旧案例中哪些能力可以学习、哪些表达和结论不能直接复制。成对成文样本保存在 `evals/writing-style-pairs.json`，只用于回归和校准，不作为事实来源。`scripts/validate_writing.py` 负责检查成文材料、案例和成对样本之间的结构关系。
