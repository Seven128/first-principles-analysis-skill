## 来源核验

2026-09-08 读取 OpenAI 官方 Model guidance 的 Using GPT-6 Astra 部分，具体位置是 [Personality and writing style](https://developers.openai.com/api/docs/guides/latest-model#personality-and-writing-style)。这是模型指南中的一节。该节有以“Avoid using slop words”开头的示例提示词，页面本身并不以这句话开头。读取的页面没有提供足以核实该节于 9 月 5 日首次上线的记录，本项目不把这个日期写成事实。

官方建议的相关方向包括：尽早说出重点，用朴素动词解释关系，减少套话、自造标签和未被问及的对立表达，按阅读需要选择格式。本记录概述相关建议，不复制完整词表或整段提示词。

## 本项目的适配

以下是针对本项目已有规则和用户反馈的取舍，不代表官方逐条原文：

- 输出规则第 5 节继续负责判断结论是否说全；第 6 节处理无信息的包装。删掉套话后仍只说半句话，依然不合格。
- 《写作规则卡》第 0、1、5 节补齐截图中的陈述句问题；第 3 节示范把抽象包装还原成已有材料支持的动作。
- 官方示例中的词汇和句式没有被复制为机械禁用表。技术术语、引语、代码标识符、真实比较、必要否定和不确定性仍须保真。
- 去掉无用的方法预告与重复收尾，不删除读者可见问题、目的型文章主链、用户要求的问答或影响结论的范围说明。
- 模型名称仅用于标明参考来源；规则按任务适用，不依赖特定模型，也不加入固定人格、口头禅或额外运行流程。

# 文件备份为何需要保留历史版本并验证恢复

## 要分析的问题

为什么一份工作文件之外，还需要独立备份、历史版本和恢复演练？

## 最终目的

文件被误删或错误覆盖后，仍能恢复所需内容。

## 当前状态与要解决的问题

目前只有一份工作文件，误删后没有其他副本可供恢复。即使增加备份，持续覆盖旧副本也可能把最后一份正确内容替换掉。备份是否能正常恢复，目前还没有得到验证。

## 采用的方案

独立备份在工作文件被误删后提供恢复副本。它补足了当前没有其他副本的问题。

历史版本保留覆盖前的内容，减少错误同步到备份后无可用旧内容的风险。只保留最新副本，仍可能同时失去工作文件和备份中的正确内容。

恢复演练检查备份能否还原所需文件。保存了副本，并不能单独说明恢复过程已经可用。

这些措施针对误删、错误覆盖和恢复未经验证的问题，不能据此保证应对所有故障。

## 验证边界

最终自动检查状态以 PR 对应提交的 GitHub Actions 记录为准。以上样例自查与程序测试不证明真实生成已稳定改善。进一步评估应固定相同材料与模型配置，在隔离上下文中比较旧版和新版，再独立检查结论完整性、信息选择、必要因果和限定是否保真。

### 未移植的机制

- 不增加每篇文章的强制脚本检测、候选全量标注、确认等待或前后对比报告；现有成文检查已经承担修复与回查，只有用户明确要求专项检测时才选择相应工作。
- 不移植特定语料与模型的阈值、倍数、指纹标签或拟改默认值；统计差异不能单独判定当前句段有错。
- 不为了句式多样而制造话题跳跃、打断必要因果、改变列表结构或删除精确信息。
- 不把某类修辞一概交给额外人审，也不靠“像真人”推断作者身份；是否改动取决于给定材料、读者任务与可说明的局部收益。

这些取舍是本项目对现有分析和写作职责的适配，不代表上游原文或上游作者为本项目背书。日常成文只读取运行规则，不重新进行来源调研。

### 新增针对性回归

`evals/local-conclusion-regression-cases.json` 新增自然表达案例，覆盖原稿视角与限定保留、功能性并列与术语保留、改稿收益不足时保持原文，以及不凭检测数值推断作者。生成输入仍只有材料与请求，评价条件留在 `evaluation`，不能作为答案提示传给生成者。

这些案例的结构校验只能证明用例完整且输入隔离；未实际生成和独立评阅的案例不能记为输出通过，也不据此宣称耗时或写作质量已有量化改善。
