# 回归方法

## 目的

回归用于判断 Skill 修改后是否仍能稳定完成两类核心任务：

1. 目标求解型：从当下状态出发，找出达到目标所需条件、缺口和方案。
2. 原理还原型：先用固定形成前基线与最终目的建立顶层缺口，再在方案部分逐项更新基线并推出当前形态。

不以逐字相似度作为通过标准。样例可能包含特定时间、版本和个人表达，真正需要保持的是分析能力。

## 执行步骤

1. 选择 `regression-cases.json` 中与本次修改最相关的案例；涉及主干逻辑时运行全部案例。
2. 使用修改后的 Skill 和案例中的 `prompt` 生成新文章。
3. 按 `global_invariants`、案例的 `must` 和 `must_not` 人工或自动审查。
4. 必要时对照 `reference` 中的既有样例，判断是否保留了相同的因果能力，而非相同措辞。
5. 记录失败发生在哪一层：问题选择、时间基线、固定比较端点、主体/层级、事实、现状与方案边界、正向推导、读者价值或表达。
6. 修复最上游的通用根因后，用同一输入重新运行。

## 最低通过条件

- 最终目的原则上只写一句，且与用户真实目标一致。
- 时间基线正确。
- 正文直接陈述对象事实，不输出问题选择、基线设定、材料分级、证据等级等内部推演过程。
- “现状与要解决的问题”始终比较同一主体、固定基线 A0 与最终目的 O。
- 现状部分只使用证明顶层能力缺口和固有限制所需的最少充分事实，没有具体任务的完整动态过程、详细方案或实现细节泄漏。
- 方案加入后的 A1、A2 和派生问题只在方案部分出现。
- 机制按依赖关系逐项正向推出。
- 每项机制都能回溯到一个已证明的顶层或派生缺口。
- 未触发时不强行加入版本比较。
- 事实、推断、假设与价值取舍分开。

## 结构校验

```bash
python3 scripts/validate_skill.py
```

该脚本只校验仓库结构、元数据、来源哈希和回归清单，不替代模型输出质量回归。
