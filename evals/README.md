# 回归方法

## 目的

回归分成推理与成文两套互补检查，并在推理套件内增加复杂输入与意图路由、关键节点校验、目的结构三组专项案例；在成文套件内增加段落、例子、代码块和重复控制专项案例。

### 推理回归

使用 `evals/regression-cases.json` 和 `evals/rubric.md`，判断 Skill 是否仍能稳定完成：

1. 把简单或复杂输入整理成正确的问题结构；
2. 定义、识别和分类；
3. 解释技术、人、组织、市场和自然结果怎样形成；
4. 分析怎样达到目标；
5. 比较和选择；
6. 混合的“为什么 + 怎么做”；
7. 将通用规则迁移到未专门举例的新主体。

### 复杂输入与意图路由回归

使用 `evals/intent-routing-regression-cases.json` 和同一份 `evals/rubric.md`，专项检查入口是否能够：

- 分离事实、用户观点、目标、限制、问题和交付要求；
- 按需要得到的独立结果提取候选问题，而不是按问号或疑问词数量拆解；
- 区分核心问题、支撑问题、独立问题和背景材料；
- 在问题关系确定后补全自包含的实际分析问题，并使它与后续路线和分析定稿一致；
- 根据对象是否已存在、行动主体、用户角色、时间方向、真正未知和期望交付识别路线；
- 识别“X 是怎么做的”可能是在问已有机制，“我怎样做 X”是在问未来行动；
- 让当前明确目标优先于历史上下文；
- 在高影响歧义下进行最少澄清，在共享主线存在时继续分析；
- 在新证据出现时重新建模，而不是固守最初标签。

该专项套件属于推理回归，不增加新的读者输出模式。它把入口错误集中出来，避免后续因果链在错误问题上继续展开。

### 关键节点校验回归

使用 `evals/node-validation-regression-cases.json` 和同一份 `evals/rubric.md`，专项检查候选原因、必要条件、方案路径和小结论在进入正式因果链前是否能够：

- 区分必要条件、充分条件、促进条件、一种实现路径和伴随关系；
- 正确区分逆否命题与否命题；
- 检查“条件存在但结果不成立”和“条件不存在但结果仍成立”；
- 发现反向因果、共同原因和替代路径；
- 区分严格命题与概率命题的反例作用；
- 在发现漏洞后修复节点，而不是只附加“存在例外”。

该专项套件同样属于推理回归，不增加新的输出模式。它只把高风险节点错误集中出来，方便在通用逻辑变更时快速定位退化。

### 目的结构专项回归

使用 `evals/purpose-structure-regression-cases.json` 和 `evals/rubric.md`，专项检查“最终目的—当前状态与要解决的问题—采用的方案”能否成为适用场景中的稳定语义链，同时避免模板化。

重点验证：

- 是否先判断对象具有明确行动主体、设计任务或用户目标；
- 最终目的是否描述外部结果和完成标准，没有提前写入具体模块、协议、算法或实现属性；
- 当前状态是否只承载事实、已有能力、限制和未知项；
- 要解决的问题是否由目的与现状之间缺少的条件推出；
- 当前状态和问题即使共用一个标题，内部语义是否仍然分开；
- 每项方案是否对应一个已经证明的问题；
- 方案改变系统状态后，是否继续分析新状态暴露的后续问题；
- 一种具体实现是否被误写成必要条件或排他的方案；
- 逻辑上的设计目的是否与真实历史意图分开；
- 定义、自然过程、群体涌现和自动情绪是否避免被强行套入目的结构。

专项案例同时包含正向和反向样本：技术系统和目标求解应建立目的链；质数定义、蚂蚁路径、猪肉周期和自动情绪不得虚构统一目的；职业选择应改用评价标准和条件化结论。

### 成文回归

使用 `evals/writing-regression-cases.json`、`evals/writing-rubric.md` 和 `evals/writing-style-pairs.json`，判断完整分析能否进一步被整理为：

- 简洁、直白、因果关系清楚的技术文章；
- 不删减关键机制的完整详细方案；
- 面向普通读者的解释文章；
- 条件化决策备忘录；
- 围绕结果链组织的经营分析报告；
- 版本边界清楚的技术演进说明。

成文回归不重新识别意图，也不重新证明分析结论。应先确认问题建模、目的结构适用性、推理和关键节点校验通过，并锁定问题结构、事实、因果、条件、不确定性和评价标准，再评价信息选择、关系表达、局部理解负担、结构去重和辅助材料控制。

新增交接检查要求：先形成包含实际分析问题、核心结论、关键因果、适用目的节点、证据边界和不得推断项的分析定稿，再建立文章类型、读者任务、职责范围与叙述视角。成稿标题后必须先呈现实质问题；目的型文章继续保留最终目的、当前状态与要解决的问题、采用的方案；正文不得出现‘用户当前材料’等生成上下文。

### 信息密度专项回归

使用 `evals/writing-density-regression-cases.json` 和 `evals/writing-rubric.md`，专项检查当前容易出现的四类成文退化：

- 把“一句推进一个主要关系”机械执行成“一句话一个段落”；
- 每个小论点分别举例，导致正文反复切换场景；
- 把普通句子、短列表和简单因果链放入代码块；
- 在开头、正文、完整案例和总结中重复同一核心结论。

专项案例要求：

- 段落由主要结论是否闭合决定，共同证明一个结论的句子留在同一段；
- 默认先用准确、具体的字面机制解释，只有存在明显理解收益时再使用例子；
- 优先使用一个能够贯穿主链的整体例子，多个例子必须承担不同且不可合并的功能；
- 代码块只用于代码、配置、精确数据、协议、复杂流程或可复制命令；
- 详细程度来自事实、因果、取舍和边界，不来自留白和展示性格式；
- 总结只收束核心结论与边界，不重新列出正文目录。

该文件同时包含成对片段，用于直接校准段落合并、微型例子压缩、普通文字去代码块、目的节点去方案泄漏和总结去重。

两套回归都不以逐字相似度为标准。真正要保持的是问题建模、场景路由、目的结构适用性、主体一致、连续因果、关键节点强度、证据纪律、中立性，以及最终交付的阅读效率。

## 成对样本

`evals/writing-style-pairs.json` 保存同一推演中的修改前后片段。它用于校准：

- 有依赖的机制是否被压成并列属性；
- 抽象名词是否隐藏主体和动作；
- 字段是否一次全部展开；
- 例子是否重复正文；
- 条件化结论是否被方法说明挡住；
- 比喻是否增加额外理解任务。

`evals/writing-density-regression-cases.json` 中的 `style_pairs` 进一步校准：

- 共同证明一个结论的单句碎段怎样合并；
- 多个只替换名词的微型例子怎样改成直接机制；
- 普通句子怎样移出代码块；
- 具体方案怎样从最终目的中移到问题与方案层；
- 总结怎样只保留核心结论和边界。

“after” 不是需要逐字复制的标准答案。评审应学习其中的变换逻辑，并检查是否保持 `must_preserve`、没有加入 `must_not_infer`。

## 执行步骤

1. 入口问题建模或路由规则变更时运行全部复杂输入与意图路由专项案例，并抽查定义、解释、行动、选择和混合问题的通用案例。
2. 目的、现状、问题或方案结构变更时运行全部目的结构专项案例，并同时抽查技术系统、人的情绪、自然系统、市场和决策案例，防止结构过度泛化。
3. 核心推理规则变更时运行全部推理案例和全部关键节点专项案例；局部主体指南变更时至少运行相关案例和两个迁移案例。
4. 成文规则变更时运行全部文章案例和全部信息密度专项案例，并至少抽查三个对应的推理案例，确认已经先形成分析定稿和文章契约，没有用压缩替代分析。
5. 对复杂输入先记录事实、观点、限制、核心问题、支撑问题、独立问题和选择路线的依据。
6. 对目的型问题记录最终目的、完成标准、当前状态、尚未成立条件、问题、设计原则、方案、验证和边界；不适用时记录为什么不启用。
7. 使用推理案例生成完整分析，记录不能改变的事实、因果、条件、不确定性和评价标准。
8. 对直接支撑最终结论的节点，检查关系类型、反例、反事实、替代路径、因果方向和证据强度。
9. 先记录分析定稿和文章契约，再使用文章案例中的 `prompt` 生成成稿；检查标题后是否呈现实质问题和适用的结构节点。
10. 先检查对应套件的 `global_invariants`、案例的 `must` 和 `must_not`。
11. 推理输出使用 `evals/rubric.md` 评分；文章输出再使用 `evals/writing-rubric.md` 评分。
12. 对照两组成对样本定位平铺依赖、抽象名词、字段百科、例子泛滥、碎段、代码块滥用和重复，不复制示例措辞。
13. 记录失败层级：输入分离、问题关系、意图路由、目的结构适用性、目的节点、当前状态、问题推导、方案映射、主体、因果、节点校验、事实、中立、信息筛选、关系平铺、段落碎片、例子密度、代码块、辅助材料或整体阅读。
14. 修复最上游的通用原因后，用同一输入重跑。
15. 结构检查通过后仍需实际模型输出评审。

## 同推演多版本测试

验证成文规则时，优先冻结同一份推演，只改变写法。建议生成：

```text
A：当前基线版
B：极度压缩版
C：新成文规则版
D：更多碎段与例子版
```

随机隐藏版本名称。先测试读者能否正确复述关键事实和因果，再询问阅读偏好。不能只问“更喜欢哪一篇”，因为故事、留白和例子可能提高主观偏好，却没有提高正确理解。

建议分开记录：

- 关键事实与因果的正确复述；
- 错误理解；
- 阅读时间；
- 回读位置；
- 主观理解难度；
- 文风偏好。

句长、术语数、段落长度和自动可读性分数只能用于相对预警，不能替代理解测试。

## 最低通过条件

### 推理套件

- 每个通用推理案例建议总分不少于 16/20；
- 不得出现 `evals/rubric.md` 中的严重错误；
- 旧核心案例不出现明显退化；
- 新增的人、组织、行业、商业、定义和迁移案例达到通过标准；
- 复杂输入与意图路由专项案例全部满足各自 `must`，且不出现 `must_not`；
- 关键节点专项案例全部满足各自 `must`，且不出现 `must_not`；
- 目的结构专项案例全部满足各自 `must`，且不出现 `must_not`；
- 技术与行动案例能够正确建立目的链，定义、自然、市场和情绪案例不被强套；
- 输出不暴露内部路由、公式和检查表；
- 通用结论只在条件成立时使用。

### 成文套件

- 每个案例建议总分不少于 10/12；
- 不得出现 `evals/writing-rubric.md` 中的严重错误；
- 标准文章不退化为研究记录、压缩报告或模块百科；
- 完整详细方案不因压缩而遗漏用户点名的关键机制；
- 已证明的依赖在成稿中可见，并行条件没有被改写成新因果；
- 每段闭合一个主要新结论，同一结论不在多个章节重复；
- 不出现贯穿全文的一句话一个段落；
- 抽象内容优先改成主体、动作和状态变化；
- 字段、术语和实现细节在成为当前答案时出现；
- 例子、表格、代码、引用和比喻只在降低理解成本或提高证据效率时使用；
- 不为每个小论点分别举例，普通文字不使用代码块展示；
- 压缩后仍保留必要因果。

## 评分记录

推理评分模板：

```text
evals/score-template.json
```

文章评分模板：

```text
evals/writing-score-template.json
```

汇总推理评分：

```bash
python3 scripts/eval_report.py scores.json
```

汇总文章评分：

```bash
python3 scripts/eval_report.py writing-scores.json --suite writing
```

## 结构校验

```bash
python3 scripts/validate_skill.py
python3 scripts/validate_intent_routing.py
python3 scripts/validate_node_reasoning.py
python3 scripts/validate_purpose_structure.py
python3 scripts/validate_writing.py
python3 scripts/validate_writing_density.py
python3 scripts/validate_conclusions.py
python3 scripts/lint_language.py --strict
```

`validate_intent_routing.py` 检查复杂输入与意图路由专项案例。`validate_node_reasoning.py` 检查关键节点专项案例。`validate_purpose_structure.py` 检查目的结构运行时规则、正向案例与反模板化案例。`validate_writing_density.py` 检查段落、例子、代码块、重复控制和对应成对片段。所有脚本都只检查仓库结构、来源哈希、指南字段、结论卡、运行时材料、回归清单、成对样本和高风险措辞，不替代模型输出质量回归与阅读理解测试。
