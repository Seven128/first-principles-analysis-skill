# 回归方法

## 目的

回归判断 Skill 修改后是否仍能稳定完成：

1. 定义、识别和分类；
2. 解释技术、人、组织、市场和自然结果怎样形成；
3. 分析怎样达到目标；
4. 比较和选择；
5. 混合的“为什么 + 怎么做”；
6. 将通用规则迁移到未专门举例的新主体。

不以逐字相似度为标准。真正要保持的是问题识别、主体路由、连续因果、证据纪律、中立性和灵活性。

## 执行步骤

1. 核心规则变更时运行全部案例；局部主体指南变更时至少运行相关案例和两个迁移案例。
2. 使用案例中的 `prompt` 生成新输出。
3. 先检查 `global_invariants`、案例的 `must` 和 `must_not`。
4. 再使用 `evals/rubric.md` 的十个维度评分。
5. 必要时对照旧案例，只比较因果能力，不复制措辞和未经核验的事实。
6. 记录失败层级：问题识别、方向、主体、因果、替代解释、事实、中立、灵活性、价值或语言。
7. 修复最上游的通用原因后，用同一输入重跑。

## 最低通过条件

- 每个案例建议总分不少于 16/20；
- 不得出现 `evals/rubric.md` 中的严重错误；
- 旧核心案例不出现明显退化；
- 新增的人、组织、行业、商业、定义和迁移案例达到通过标准；
- 输出不暴露内部路由、公式和检查表；
- 通用结论只在条件成立时使用。

## 结构校验

```bash
python3 scripts/validate_skill.py
python3 scripts/lint_language.py
```

这些脚本检查仓库结构、来源哈希、指南字段、结论卡、回归清单和高风险措辞，不替代模型输出质量回归。
