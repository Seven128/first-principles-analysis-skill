# First Principles Analysis Skill

一套把模糊或复杂输入转化为清晰问题结构和连续因果分析，并进一步整理成有效信息密度高、局部理解负担可控成稿的 Skill。

v2 将能力拆成四层：

```text
复杂输入的问题建模、场景化意图识别、通用因果推理与关键节点校验
+
不同主体需要优先检查的变量
+
带适用条件和失效边界的通用结论
+
把完整推演转换成读者容易正确理解的交付形式
```

目标是先找对问题和推理方向，再让分析因果严密，同时让最终输出简洁、直白、直接。成文不以字数最短为目标，而是在保持事实、因果、条件和不确定性的前提下，降低读者获得正确理解所需的成本。

## 能处理什么

- 从长段输入中分离事实、用户观点、目标、限制、问题和交付要求；
- 识别一个核心问题及其支撑问题，或保留多个彼此独立的问题；
- 不依赖“是什么、为什么、怎么做”等问句形式，根据场景识别定义、解释、行动、判断和混合意图；
- 定义、识别和分类；
- 解释技术、行为、组织或市场结果怎样形成、运行或被实现；
- 分析怎样达到一个目标；
- 比较方案和作出条件化判断；
- 混合的“为什么会这样 + 接下来怎么办”；
- 校验关键原因、必要条件、方案路径和小结论是否遗漏条件或替代路径；
- 把复杂分析整理成文章、报告、方案或直接回答；
- 迭代 Skill、扩展主体指南、结论卡和回归案例。

## 核心变化

### 1. 复杂输入先建立问题结构

用户说得长，不代表问题多；用户只说一句，也可能包含多个不同目标。入口先把输入分成：

```text
事实与材料
+
用户观点和候选前提
+
目标、限制与评价标准
+
明确或隐含的问题
+
期望交付
```

再判断候选问题之间的关系：

```text
核心问题
→ 回答后最能改变当前理解、判断或行动

支撑问题
→ 回答核心问题所需的前提、证据或中间判断

独立问题
→ 有自己的对象、结果和交付，可以单独成立
```

有依赖的问题按真实顺序展开；独立问题不为了结构整齐被强行合并。同一核心问题也不因多个问句被拆成互相重复的并列回答。

### 2. 问句形式不直接决定意图

“是什么、为什么、怎么做”仍可作为底层推理方向，但疑问词只提供弱线索。入口同时检查：

- 对象或结果是否已经存在；
- 谁形成、运行、改变或选择结果；
- 用户是观察者、判断者、行动者，还是要求助手直接执行；
- 时间方向是解释过去和现在，还是从现在走向未来；
- 用户真正缺少的是边界、事实、原因、机制、路径、标准还是选择结果；
- 需要解释、判断、方案、步骤还是实际操作。

因此：

```text
“Agent 的工具调用是怎么做的？”
→ 通常是在理解已有对象的实现和运行机制

“我准备给自己的 Agent 加工具调用，应该怎么做？”
→ 是从当前状态达到尚未实现目标的行动问题

“Agent 的工具调用是怎么做的？我也要实现一个。”
→ 先解释已有机制，再设计用户的实现路径
```

当前明确目标优先于历史上下文。存在歧义时，只有不同理解会产生明显不同交付，才提出能够区分路线的最少澄清；否则先回答共享主线，或声明暂定范围后继续。

### 3. “是什么”不再一律改成“为什么”

纯定义和分类直接回答边界；当前事实直接确认；只有用户真正需要形成原因、运行过程或内部机制时，才转入解释路线。

### 4. 两条主要因果推理主线

解释已经存在的结果：

```text
结果
→ 长期条件
→ 直接触发
→ 中间作用过程
→ 维持和放大因素
→ 替代解释与证据
```

达成尚未实现的目标：

```text
目标和完成标准
→ 候选必要条件
→ 当前情况
→ 尚未成立的条件
→ 多条路径
→ 取舍、执行、验证和调整
```

判断、选择和混合问题会组合这些基础方向，但不会把过去形成原因和未来行动混成一条模糊链。

### 5. 关键节点进入因果链前先做反向校验

对直接支撑结论或行动选择的节点，先判断它声称的是必要条件、充分条件、促进条件、一种实现路径还是伴随关系，再检查：

```text
条件存在但结果没有出现
→ 是否遗漏共同条件、作用过程或抑制因素

条件不存在但结果仍然出现
→ 是否存在替代原因或替代路径

A 与 B 同时出现
→ 是否可能反向因果、共同原因或双向强化
```

严格命题与概率命题使用不同的反例标准。发现漏洞后必须补条件、增加替代路径、降低结论强度、缩小范围或删除节点，不能只附一句“存在例外”。这一步属于内部推演，默认不把检查表写进最终文章。

### 6. 主体指南按需加载

当前包含：

- 人的行为与情绪；
- 群体与组织；
- 技术系统与产品；
- 行业市场与资源流动；
- 商业与赚钱；
- 制度与政策；
- 自然与生物系统。

指南只提供优先检查方向，不强制填充所有变量。

### 7. 通用结论使用结论卡

当前包含：

- 利益关系链；
- 资源分配；
- 反馈延迟与周期；
- 人的行为与情绪；
- 信息、能力与时间差；
- 资金流向。

每条卡都包含成立条件、失效范围、证据和常见误用。结论卡产生的仍是候选节点，需要经过当前问题的事实筛选和关键节点校验。

### 8. 客观不等于替用户决定价值标准

Skill 不默认长期优于短期、稳定优于波动、持续优于一次性。方案比较使用用户明确选择的目标，同时说明法律、规则、安全、成本和后果。

### 9. 完整推演与最终成文分离

分析阶段先保证问题结构、事实、因果、关键节点强度、替代解释和证据边界完整。用户需要文章、报告或完整方案时，再执行成文转换：

```text
问题建模与场景路由
→ 完整推演与节点校验
→ 锁定问题结构、事实、因果、条件、结论强度和不确定性
→ 识别文章任务与读者
→ 提取最小完整因果主线
→ 按真实依赖生成段落骨架
→ 拆解超载句并把抽象名词还原成动作
→ 按需加入例子，最后才考虑比喻
→ 去重、校准详细程度
→ 四层检查
→ 回查推演不变量
```

这同时避免四类退化：

- 严密地回答了错误的问题；
- 把研究记录和内部检查表当文章；
- 把多项机制压成抽象名词和属性清单；
- 为了简洁删断因果，或为了生动增加新的理解任务。

### 10. 有效信息密度

目标不是单位字数放入最多概念，而是：

```text
读者正确理解并能够使用的关键信息
÷
获得这些信息所需的理解成本
```

因此，高质量成稿既要持续增加有效信息，也要控制每个局部同时引入的新关系。句子不必全部很短，段落也没有固定长度；结构边界应与真实逻辑边界一致。

## 使用

将本仓库作为 Skill 安装后，用户可以直接提出问题，例如：

- Agent 到底是什么，为什么会形成现在这种结构？
- 数据库索引是怎么做的？
- 我准备自己实现一个简化索引，应该怎么做？
- 为什么同事在我指出错误后生气？
- 为什么团队总在争核心项目？
- 猪肉价格为什么可能周期波动？
- 我怎样利用 AI 赚钱？
- 我应该留在当前公司还是接受新 Offer？
- 我得出“开车上班就不会迟到”，怎样检查这个小结论是否漏了条件？
- 我说了很多背景和多个问句，请先梳理核心问题、支撑问题和独立问题，再分析。
- 把以上分析写成一篇简洁、直白、因果完整的技术文章。

Skill 会先在内部整理输入、建立问题结构、选择场景化推理路线和相关主体指南，校验关键节点，再按用户需要输出直接回答或成稿，不展示内部路由和检查脚手架。

## 验证

```bash
python3 scripts/validate_skill.py
python3 scripts/validate_intent_routing.py
python3 scripts/validate_node_reasoning.py
python3 scripts/validate_writing.py
python3 scripts/validate_conclusions.py
python3 scripts/lint_language.py --strict
```

推理质量按照 `evals/rubric.md`、`evals/regression-cases.json`、`evals/intent-routing-regression-cases.json` 和 `evals/node-validation-regression-cases.json` 评审。文章质量按照 `evals/writing-rubric.md`、`evals/writing-regression-cases.json` 和 `evals/writing-style-pairs.json` 评审。结构校验不能替代实际模型输出回归和阅读理解检查。

## 原始来源

v1 的逻辑、提示词、经验和长篇案例继续保留，并由 `references/source-manifest.json` 校验哈希。v2 将它们视为历史来源和回归材料，而不是每次分析都完整加载的运行时提示词。
